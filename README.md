# Aniart VR

Плеер для Meta Quest 3S с лёгким кинозалом OpenXR, пространственным каталогом и управлением лазером контроллера. Android Media3 воспроизводит HLS и MP4. В каталоге можно найти тайтл, выбрать серию, озвучку и качество, добавить тайтл в избранное и продолжить с сохранённой позиции.

## Сборка и установка

Понадобятся Git, Python 3, JDK 17 и Android SDK. Gradle wrapper 8.5 входит в закреплённый исходник Khronos. Сборка предназначена для `arm64-v8a`, Android API 31 и выше.

```sh
sdkmanager 'platforms;android-34' 'build-tools;34.0.0' 'ndk;23.2.8568313' 'cmake;3.22.1' 'platform-tools'
./build.sh
find .build/openxr/src/tests/hello_xr/build/outputs/apk/debug -name '*.apk'
adb install -r .build/openxr/src/tests/hello_xr/build/outputs/apk/debug/hello_xr-debug.apk
adb shell am start -n dev.aniart.vr/.CinemaActivity
```

Для sideload на Quest требуется режим разработчика и разрешённый на шлеме ADB. Сборку можно скачать в разделе Artifacts успешного запуска [GitHub Actions](https://github.com/ytpk/aniart-vr/actions). Если обновление поверх предыдущего CI APK выдаёт `INSTALL_FAILED_UPDATE_INCOMPATIBLE`, подписи двух debug-сборок различаются. Перед удалением предыдущего **Aniart VR** сохраните свой каталог. Удаление приложения также стирает локальные настройки и позиции просмотра.

| Контроллер | Действие |
| --- | --- |
| Любой курок | Нажать кнопку, на которую наведён лазер. При скрытых элементах управления — показать панель плеера |
| A | Продолжить или поставить на паузу |
| B | Назад или скрыть панель просмотра |
| X | Открыть каталог |
| Y | Показать или скрыть панель просмотра |
| Левый стик | Листать страницы каталога. При просмотре — перемещать экран |

В плеере доступны пауза, перемотка по шкале, шаг ±10 секунд, переключение на следующую серию, скорость и громкость. В настройках доступны автопереход между сериями, размер экрана, Anime4K, A/B и стерео. Звук и положение воспроизведения сохраняются локально. Первое нажатие курка при скрытой панели только открывает её.

## Звук и обстановка кинозала

Кинозал использует геометрию OpenXR: диван, настенные панели, красную подсветку, потолочные светильники и экран в тёмной нише.

Включите «Звук зала» в настройках плеера. Media3 передаёт декодированный PCM в процессор виртуальных колонок. Для входа 7.1 он использует восемь каналов, для 5.1 — шесть. Для моно и стерео строит пространственный эффект из исходных каналов. На выходе остаются два канала для наушников или динамиков Quest. Используются разница уровня и задержки между ушами, затенение дальнего уха, отражения от боковых стен, задней стены и потолка и короткий затухающий хвост. Горизонтальный поворот головы считывается из OpenXR. При включённом эффекте Android spatializer отключён для этой дорожки.

Офлайн-ролик «Проверка звука 7.1» по очереди воспроизводит тестовый сигнал в каждом канале. Настройки показывают число каналов, полученное после декодирования. Если аппаратный декодер или источник даёт стерео, применяется эффект для стерео. Переключение эффекта переоткрывает текущую дорожку и сохраняет позицию у перематываемых роликов.

## Каталог и Kodik

### Вкладка Anixart

Вкладка открывает гостевую подборку «Смотрят сейчас». Поиск использует серверную выдачу Anixart. Карточки показывают постер, год и число вышедших серий, если поля есть в ответе. Маршрут просмотра — тайтл → озвучка → источник → серия. Избранное и импортированные файлы доступны во вкладке «Локальное».

Прямые HTTPS-потоки HLS/MP4 открываются в VR-плеере. При выборе серии Kodik плеер запрашивает свежую страницу встраивания и читает список выданных ей потоков. На первом месте 720p, если источник его предлагает, затем доступные варианты меньшего разрешения. Дополнительные качества выбираются в карточке серии. Плеер передаёт Referer провайдера. URL и исходные параметры серии используются в текущем сеансе.

Если Kodik не отдаёт доступный поток, карточка показывает ошибку и предлагает обновить ссылки или открыть веб-плеер. При передаче прямой ссылки SolodCDN через «Поделиться» Aniart VR сам добавит Referer Kodik. Заголовки для других источников можно задать в JSON. Авторизация Anixart и синхронизация истории отсутствуют.

Форматы ответов сверены с [неофициальной документацией Anixart](https://openanix.ru/anixart-api-docs/), [AniX Player Parsers](https://github.com/AniX-org/anix-player-parser) и [анализом плеера в anime-dl-core](https://github.com/ialakey/anime-dl-core).

Если Kodik вернул прямой URL с `/480.mp4` или `/480.mp4:hls:manifest.m3u8` на своём CDN, Aniart VR может проверить соседний вариант `/720.mp4:hls:manifest.m3u8`. HTTPS-хост, каталог, строка запроса и заголовки остаются прежними. Вариант появляется в карточке после ответа HTTP 200 с HLS-плейлистом. Оригинальная ссылка остаётся доступна. Разрешение декодированного кадра видно в плеере.

### Параллельный источник через ani-cli-ru

Установите `anicli-ru==6.1.3` в Python-окружение на ПК. Экспортёр получает свежую серию из AniLiberty через библиотеку проекта, сохраняет сайт-источник, качество и HTTP-заголовки в JSON. Импортируйте файл в **Настройки → Импорт каталога** или через ADB. Файл может содержать временные ссылки.

```sh
python3 tools/export_anicli.py 'Наруто' --release 1 --episode 370 --quality 720 > catalog.local.json
```

Для просмотра номеров тайтлов при неоднозначном поиске запустите команду без `--release`. [ani-cli-ru](https://github.com/vypivshiy/ani-cli-ru)

### Проверка каталога Anixart

`./tools/check_anixart.sh` запускает тесты с JDK 17. Они используют производственный адаптер и цепочку выбора потока: поиск, озвучка, источник, серия, передача прямого HLS, выбор 720p или доступного 480p, обработка ошибок Anixart/Kodik. Ответы тестового источника синтетические. Проверка входит в CI.

`./tools/check_anixart.sh --live` дополнительно делает гостевые запросы к Anixart для двух тайтлов и при наличии прямого URL проверяет ответ CDN. Команда печатает, на каком этапе остановился источник. Код выхода 2 означает, что в живой проверке медиапоток получить или открыть не удалось. Личные ссылки и токены тесту не нужны.

### Передача потока из Anixart

В предоставленном APK Anixart 10.5 URL страницы Kodik и URL медиапотока проходят разные этапы. Парсер запрашивает варианты качества через отдельную интеграцию Kodik. Патч выбора качества получает готовый CDN URL и передаёт его во внешний плеер через Android `ACTION_VIEW` с типом `video/*`, заголовками и названием. Прямая ссылка содержит `.m3u8` или `.mp4`. Адрес вида `kodikplayer.com/video/…` открывает страницу.

В патченом Anixart выберите качество и нажмите «Копировать полный URL». Затем в Aniart VR откройте серию и нажмите «Вставить прямой поток» либо используйте «Локальное → Вставить ссылку». Появится карточка для подтверждения. Aniart VR также принимает системное «Поделиться» и `ACTION_VIEW` с типом видео. Из переданных заголовков поддерживаются User-Agent, Referer и Origin. Приложение Anixart из вложения адресует свой вызов пакету mpvRx. Для этой сборки используйте копирование URL.

### Локальные источники

В комплекте есть HLS, MP4 и офлайн-ролик SBS. Пользовательские записи можно добавить через «Настройки → Импорт каталога» на устройствах с системным выбором файла. Также поддерживается загрузка `catalog.json` через ADB.

```sh
adb shell am force-stop dev.aniart.vr
adb shell 'run-as dev.aniart.vr mkdir -p files'
adb shell 'run-as dev.aniart.vr sh -c "cat > files/catalog.json"' < catalog.local.json
adb shell am start -n dev.aniart.vr/.CinemaActivity
```

Каждая запись связывает тайтл, серию, озвучку и качество с одним HTTPS-потоком. `type` принимает `hls` или `mp4`. Необязательное поле `stereo` принимает `2d`, `sbs` или `ou`. Формат сохраняет совместимость с предыдущим JSON.

```json
[
  {
    "title": "Название",
    "episode": "Серия 1",
    "voice": "Оригинал",
    "quality": "720p",
    "url": "https://example.org/episode/720.mp4:hls:manifest.m3u8",
    "type": "hls",
    "headers": {"Referer": "https://example.org/"}
  }
]
```

Для Kodik передавайте проверенный URL 720p. `quality` служит подписью. Для многовариантного HLS Media3 адаптивно выбирает трек. Заголовки применяются к запросам этого источника, включая манифесты, сегменты и хосты, задействованные ими. Используйте доверенные URL и манифесты. Серии и варианты выводятся в порядке записей. При автопереходе плеер сначала ищет ту же озвучку и качество. Если источник позволяет поделиться прямой HTTPS-ссылкой на `.m3u8` или `.mp4`, её можно передать в Aniart VR через «Поделиться» или `ACTION_VIEW`. Плеер открывает карточку ссылки и ждёт подтверждения. Ссылку с нужными HTTP-заголовками добавляйте через JSON. Ссылка на страницу тайтла не является медиапотоком.

```sh
adb shell am start -n dev.aniart.vr/.CinemaActivity \
  -a android.intent.action.VIEW -d 'https://example.org/episode.m3u8'
```


## Anime4K и стерео

Включите A/B в настройках или в плеере. Панель показывает разрешение декодированного кадра, состояние фильтра и активный режим стерео. Кнопка «2D → 3D» прямо в плеере включает псевдоглубину для обычного видео. Оба сетевых демо изначально плоские. «Big Buck Bunny» использует фиксированный HLS-вариант 720p для повторяемого сравнения. Левая половина экрана покажет исходное видео, правая — результат Anime4K. Облегчённый профиль использует оригинальный CNN x2 S из семейства Fast. Четыре CNN-прохода и финальный x2 выполняются для нового кадра. При активном SBS/OU обработка выполняется отдельно для каждого ракурса. Фильтр принимает до 1920×1080 в 2D и до 1280×720 пикселей на глаз в SBS/OU с учётом площади и размеров кадров. На слишком больших кадрах остаётся исходное изображение. В настройках видны FPS и, при поддержке таймера драйвером, время GPU.

- **SBS / OU.** OpenXR показывает левому и правому глазу соответствующую часть упакованного кадра. Поддерживается перестановка глаз. Пропорции full/half упаковки оцениваются по геометрии кадра.
- **Псевдо-3D.** Обычное 2D-видео получает регулируемый параллакс. Стереошейдер использует небольшую карту яркости и положения на экране. Карта не определяет расстояние до объектов. Настройка глубины доступна в этом режиме, включая нулевой параллакс.
- **Комбинации.** Anime4K и A/B доступны со всеми режимами. Псевдоглубина вычисляется по исходному кадру, а смещение применяется к исходному или улучшенному изображению.

Media3 выводит декодированные кадры в `SurfaceTexture`. Имя фактического декодера видно в `adb logcat -s AniartVR`. Для 2D используется внешняя текстура OES. Обработка предшествует отрисовке двух глаз. Точка будущего подключения модели глубины — карта перед стереошейдером с привязкой к кадру и ограниченной очередью.

### Apple Depth Pro 2

Apple публикует для **DepthPro2-S** 24 млн параметров и веса размером около 97 МБ. Официальный вариант Core ML занимает около 53 МБ и предназначен для Apple-платформ. Отдельный оценщик фокусного расстояния добавляет около 94 МБ в PyTorch-конфигурации, где нужно вычислять неизвестный фокус. Показатели Apple по стабильности глубины и краям измерены на Sintel и Spring. Для Quest важны собственные измерения на аниме и совместно с Anime4K. Лицензия весов ограничивает применение научными исследованиями и академической разработкой. В пользовательский APK веса не входят. [Модель Small](https://huggingface.co/apple/DepthPro2-S), [Core ML](https://huggingface.co/apple/DepthPro2-coreml), [лицензия модели](https://github.com/apple-aiml-research/ml-depth-pro-2/blob/aa389cbb0b74341664ed663a0966c859905cd6c0/LICENSE_MODEL).

## Почему отдельный проект

Thru3D использует Godot/GDScript, Android Kotlin-плагины, собственный source-frame мост libmpv/FFmpeg, нативные рендер- и XR-слои и отдельные ветки для глубины и маттинга. В публичном исходнике `55c905a` приложение GPL-3.0-only. Документация сборки требует конкретные шаблоны Godot/OpenXR Vendors, собранные нативные библиотеки, подготовленные модели и внешние ресурсы сцен. Дистиллированные веса маттинга отсутствуют в Git. Полную сборку Thru3D в этом проекте не проверяли. Использование mpvRx (AGPL-3.0 по README) здесь ограничено сравнением воспроизведения на Quest.

- [Сборка Thru3D](https://github.com/zerochocobo/Thru3D-Media-Player/blob/55c905a1cfa5b15d6d1df2f0de514084c149daa2/docs/BUILD.md)
- [Архитектура Thru3D](https://github.com/zerochocobo/Thru3D-Media-Player/blob/55c905a1cfa5b15d6d1df2f0de514084c149daa2/docs/ARCHITECTURE.md)
- [Лицензии Thru3D](https://github.com/zerochocobo/Thru3D-Media-Player/blob/55c905a1cfa5b15d6d1df2f0de514084c149daa2/docs/LICENSING.md)
- [mpvRx](https://github.com/Riteshp2001/mpvRx)

Базовый рендер и OpenXR loader получены из Khronos OpenXR SDK Source `47c4761`. Файл `openxr-cinema.patch` содержит изменения примера Android/GLES. Шейдер Anime4K взят из `7684e9586f8dcc738af08a1cdceb024cc184f426` и преобразуется из mpv hook-формата в GLES при сборке. Тексты лицензий поставляются вместе с APK. AndroidX Media3 1.4.1 загружается из Google Maven.

## Проверка на Quest 3S

1. Наведите луч на карточку «Лунный пролёт», нажмите курок и выберите вариант воспроизведения. Раскладка SBS выбирается автоматически. Если ранее меняли её для этого тайтла, выберите SBS в настройках.
2. Включите A/B на панели плеера. Проверьте различие резкости слева и справа экрана, затем переставьте глаза в настройках и верните нормальный порядок.
3. Откройте MP4 «Sintel», попробуйте псевдо-3D на малой глубине с включённым Anime4K. Проверьте перемотку, сохранение позиции и возврат в каталог.
4. Откройте свой Kodik HLS с заголовками. Проверьте декодер, FPS и время GPU, затем повторите после длительного просмотра. Отдельно оцените комфорт стерео в шлеме.

Для проверки пересечения лазера с панелями на ПК после сборки можно запустить `tools/check_pointer.cpp` с C++17 и заголовками OpenXR из дерева CMake. Для обновления офлайн-ролика используйте `python3 tools/make_stereo_demo.py` с Pillow и FFmpeg.
