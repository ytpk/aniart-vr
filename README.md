# Aniart VR

Прототип плеера для Meta Quest 3S. Нативный OpenXR рисует лёгкий кинозал из плоскостей. Android Media3 воспроизводит HLS и MP4 на пространственном экране. Каталог показывает название, серию, озвучку и качество из подключённого источника.

## Сборка и установка

Понадобятся Git, Python 3, JDK 17 и Android SDK. Gradle wrapper 8.5 входит в закреплённый исходник Khronos. Сборка предназначена для `arm64-v8a`, Android API 31 и выше.

```sh
sdkmanager 'platforms;android-34' 'build-tools;34.0.0' 'ndk;23.2.8568313' 'cmake;3.22.1' 'platform-tools'
./build.sh
find .build/openxr/src/tests/hello_xr/build/outputs/apk/debug -name '*.apk'
adb install -r .build/openxr/src/tests/hello_xr/build/outputs/apk/debug/hello_xr-debug.apk
adb shell am start -n dev.aniart.vr/.CinemaActivity
```

Для sideload на Quest требуется режим разработчика и разрешённый на шлеме ADB. Debug APK также доступен как артефакт успешного запуска GitHub Actions. Для повторной установки из другого источника подпись debug-ключа может отличаться.

| Контроллер | Действие |
| --- | --- |
| Левый / правый курок | Предыдущая / следующая позиция каталога |
| A | Открыть выбранное видео, затем поставить на паузу или продолжить |
| B | Включить или выключить Anime4K |
| X | Показать или скрыть каталог |
| Y | Переключить размер экрана |
| Левый стик | Переместить экран |

## Каталог и Kodik

Есть две демонстрационные записи, HLS и MP4. Дополнительные потоки подаются через локальный `catalog.json` с тем же форматом, что в `overlay/src/main/assets/catalog.json`. Каждая строка связывает сериал, эпизод, озвучку и вариант качества с одним разрешённым HTTPS-потоком. Поле `type` принимает `hls` или `mp4`. Поле `headers` опционально и принимает объект строк, например `{"Referer":"https://example.org/","User-Agent":"Example Player"}`. Media3 использует эту конфигурацию для HTTP-запросов к источнику, включая HLS-манифесты и сегменты. Заголовки применяются ко всем хостам, которые задействует данный источник. Используйте каталог с доверенными URL и манифестами.

```sh
adb shell am force-stop dev.aniart.vr
adb shell 'run-as dev.aniart.vr mkdir -p files'
adb shell 'run-as dev.aniart.vr sh -c "cat > files/catalog.json"' < catalog.local.json
adb shell am start -n dev.aniart.vr/.CinemaActivity
```

Для 720p передавайте проверенный прямой URL. Поле `quality` служит подписью строки. Единственный вариант в HLS будет воспроизводиться как есть; для многовариантного манифеста Media3 адаптивно выбирает трек. Будущий адаптер Anixart реализует `Catalog.load`, преобразуя ответ документированного API или согласованного экспорта в список `Episode`. Поиск, авторизация, кеш постеров и выбор озвучки по отдельным группам относятся к этому адаптеру и экрану каталога. Подключение живого Anixart и подтверждение реального потока Kodik 720p ожидают источник и тест на устройстве.

## Видеоконвейер

1. Media3 ведёт HLS/MP4, аудио и буферизацию. Android MediaCodec выводит кадры в `SurfaceTexture`. Фактический декодер виден в `adb logcat -s AniartVR`. Декодер выбирает Media3, аппаратность конкретного трека нужно подтвердить на Quest.
2. GLES использует текстуру OES напрямую в режиме 2D. При включении Anime4K вход копируется в RGBA8 и выполняются оригинальные четыре CNN-прохода Anime4K x2 S и перестановка каналов в выход x2. Этот облегчённый профиль включает один upstream-шейдер из семейства Fast. Состав каскада Mode A (Fast) в mpv шире.
3. Обработка выполняется один раз на новый видеокадр до отрисовки обоих глаз, с буферами RGBA16F для знаковых промежуточных значений. Обработка ограничена входом до 1920×1080. При недоступности шейдера и FBO доступно исходное изображение. Панель показывает FPS отрисовки и время GPU для Anime4K при наличии `GL_EXT_disjoint_timer_query`.
4. OpenXR подаёт сцену отдельно для каждого глаза. Сегодня оба глаза видят одну видеотекстуру на плоскости. Точка интеграции глубины находится между обработанным кадром и `Screen::Draw`. План для AI-3D — извлекать карту на меньшем входе с очередью на один кадр, привязывать её к PTS, сглаживать между кадрами и строить левый и правый виды с ограниченной диспаратностью, регулируемой глубиной и заполнением открывшихся пикселей. Начать можно с Depth Anything V2 Small после проверки лицензии выбранных весов и GPU-бэкенда устройства. При отставании инференса стереоэтап должен оставлять валидную пару или переключаться в 2D.

## Почему отдельный проект

Thru3D использует Godot/GDScript, Android Kotlin-плагины, собственный source-frame мост libmpv/FFmpeg, нативные рендер- и XR-слои и отдельные ветки для глубины и маттинга. В публичном исходнике `55c905a` приложение GPL-3.0-only. Документация сборки требует конкретные шаблоны Godot/OpenXR Vendors, собранные нативные библиотеки, подготовленные модели и внешние ресурсы сцен. Дистиллированные веса маттинга отсутствуют в Git. Полную сборку Thru3D в этом проекте не проверяли. Использование mpvRx (AGPL-3.0 по README) здесь ограничено сравнением воспроизведения на Quest.

- [Сборка Thru3D](https://github.com/zerochocobo/Thru3D-Media-Player/blob/55c905a1cfa5b15d6d1df2f0de514084c149daa2/docs/BUILD.md)
- [Архитектура Thru3D](https://github.com/zerochocobo/Thru3D-Media-Player/blob/55c905a1cfa5b15d6d1df2f0de514084c149daa2/docs/ARCHITECTURE.md)
- [Лицензии Thru3D](https://github.com/zerochocobo/Thru3D-Media-Player/blob/55c905a1cfa5b15d6d1df2f0de514084c149daa2/docs/LICENSING.md)
- [mpvRx](https://github.com/Riteshp2001/mpvRx)

Базовый рендер и OpenXR loader получены из Khronos OpenXR SDK Source `47c4761`. Файл `openxr-cinema.patch` содержит изменения примера Android/GLES. Шейдер Anime4K взят из `7684e9586f8dcc738af08a1cdceb024cc184f426` и преобразуется из mpv hook-формата в GLES при сборке. Тексты лицензий поставляются вместе с APK. AndroidX Media3 1.4.1 загружается из Google Maven.

## Проверка на Quest 3S

Откройте оба демо, проверьте звук, геометрию экрана и отсутствие переворота кадра. Переключите B несколько раз на одном эпизоде, включая паузу. Затем проверьте собственный HLS 720p с заголовками. Сравните FPS и GPU ms в 2D и с Anime4K, запишите декодер из logcat и повторите после 15 минут воспроизведения. Сборка APK сама по себе не подтверждает совместимость рантайма Quest, плавность или качество фильтра.
